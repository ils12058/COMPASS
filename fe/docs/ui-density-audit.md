# UI information hierarchy audit and delivery (ADR-091)

Baseline: `origin/staging` **7640f63ad45ff4710a9cba866c314d8710c92483**, fetched October 7, 2026 (Asia/Manila). PR #187 / ADR-090 was already merged. Implementation branch: `codex/ui-information-hierarchy`. The final Git commit/PR identifies the delivered head; this document does not invent a self-referential commit SHA.

## Audit scope and method

Before source edits, reviewed all 107 route pages and the active frontend's 502 source files. Static inventory: 477 button/action occurrences, 121 Notices, 902 paragraphs. These are source counts, including conditional branches, not counts displayed simultaneously. Archived frontends and generated wire code were excluded from edits.

Searched every PageHeader/feature heading and PanelHeader description, Notice, PanelMessage, paragraph, button/action group, dialog/form, title and accessible label; reviewed record/list/workspace, responsive/card, and icon patterns. The retained inventory included 324 longer text occurrences. Read the high-priority compositions and their state/action/error helpers in full context. Density is qualitative, not a font-size score: High mixes work and permanent explanation; Medium is complex but much of its detail is needed to act or answer correctly; Low already has concise state/actions.

All explanatory copy was classified before editing:

| Category | Placement |
| --- | --- |
| A: current state | Visible alongside its record or live session |
| B: required next action | Visible where relevant |
| C: error, warning, blocker | Visible Notice, PanelMessage or inline status/alert |
| D: action consequence | Confirmation/review or immediately beside a consequential setting |
| E: conceptual/domain explanation | Grouped page Help; optional section Help only for genuine complexity |
| F: input constraint | Concise text close to the field |

Audited pages: **12 High / 32 Medium / 63 Low**. The matrix covers every active page, including intentional preservation decisions.

## Shared interaction and copy decisions

- `ContextHelp`: visible Help/CircleHelp button with a contextual accessible name; named modal Dialog with grouped headings and optional links. Uses the existing Radix focus trap, Escape dismissal and return-focus implementation. One page entry per complex workspace, no question marks beside fields. A scrollable, viewport-bounded 2xl dialog works on phones.
- `Tooltip`: narrow Radix Tooltip dependency, 300ms hover delay, immediate keyboard focus, Escape dismissal, hoverable content, portal and viewport collision handling. Only short names; no critical information or interactive documentation. References: [Radix Tooltip](https://www.radix-ui.com/primitives/docs/components/tooltip), [WAI tooltip pattern](https://www.w3.org/WAI/ARIA/apg/patterns/tooltip/).
- `IconAction`: constrained common vocabulary for back, download, edit, more, refresh, search and settings; real button, explicit `aria-label`, decorative Lucide icon and tooltip. Coarse-pointer devices also show the name, so touch needs no hover or extra tap. Consequential controls keep text.
- Existing PageAction/PageActionLink remain the main page-command pattern. SortField, SortableColumnHeader and ADR-090 query/ordering behavior remain unchanged.
- Notices now emphasize actual warning/error/blocked/consequential states. Permanent Environment startup documentation is disclosed in Help, with the server's exact diagnostic text. Ordinary Institutional Form and Inventory history empty/loading states use lighter in-panel content.
- PageHeader accepts optional Help next to actions, with wrapping at narrow widths. Feature wrappers forward it. Institutional Forms and Environment have one short description; E-Counseling leads with participant, time and appointment status. Panel descriptions explain the immediate task; repeated domain tutorials moved to Help.
- Copy describes the result and next safe action. Unknown API messages are still filtered by existing presentation helpers. No existence/ownership/access boundary is made more specific.

## Intentionally retained detail and terms

Individual Inventory, Exit Interview, Graduate Tracer, Customer Feedback and CSM retain approved questions, answer instructions/scales and confidential/voluntary-participation meaning. Routine Intake/Evaluation keep student instructions and the evaluation scale. Public pages, Reports, simple lists and account/security pages remain largely intact because their explanations carry actual scope, coverage, audience, security or input consequences.

Remaining implementation-like words are confined to source identifiers/comments, Help explaining genuine concepts, or true operator/document concepts: Service provider coverage is an institutional configuration; Platform dependencies/resolved configuration/startup are diagnostics; retention provider artifacts, eligibility, evidence and disposition are governance concepts; source/form revision distinguishes the paper document from current account identity; COMPASS support is the controlled-form registry's actual support status. They are not introduced into ordinary Student error copy. Active media state may appear both on the sticky session stage and its stop control for safety while working; no consent approval is presented as activity.

The final AST/string and rendered-copy review found two visible occurrences from the explicit engineering-term watchlist, both retained at the governance decision:

| Remaining term | Location and justification |
| --- | --- |
| Reconciliation required | `retention-shared.tsx`, disposition status. An operator must reconcile a failed/unconfirmed disposition before retry; this is the actual governance state, not a generic technical error |
| minimized lifecycle evidence | `retention-shared.tsx`, irreversible provider-artifact disposition consequence. Precisely distinguishes the minimized evidence and consent decisions that remain from the media artifact that will be deleted; preserving that retention meaning is necessary before approval |

Other watchlist matches are imports, internal state/IDs or comments, not visible product copy. Controlled source-document identity, diagnostic results and institution-authored/user-authored content retain their exact meaning.
