# Encryption, lineage, cutover and recovery

## Purpose and configuration contract

Source/settings tests PASS with synthetic keys. `STUDENT_SESSION_SUMMARY_ENCRYPTION_KEYS` and `ROUTINE_INTERVIEW_ENCRYPTION_KEYS` are required; the Handoff ring `COUNSELOR_HANDOFF_SUMMARY_ENCRYPTION_KEYS` may be absent/empty at inert startup, while body operations safely deny. Supplied malformed, duplicate or shared keys reject startup. `_FILE` and direct settings cannot conflict; supplied missing/unreadable files fail rather than falling back. Empty optional Handoff contents are permitted by the runtime inventory, but the declared file and correct pointer/mode/owner remain required by the staging Compose/preflight contract.

Handoff separation is tested against Django SECRET_KEY, TOTP, Push storage, Routine, Student Summary, Referral, Exit Interview, Inventory, Tracer, account profile, Feedback, Guidance Messages, Assessment and Follow-Up keys. Reusing any tested purpose key fails without exposing its value. First key encrypts; all configured keys decrypt. Only ephemeral/local synthetic keys are used; no live secret is inspected or provisioned.

Handoff schema 1 binds document UUID, Grant UUID, Student UUID, author UUID and exact receiving Counselor UUID; payload is exactly `{content}`. Wrong keys, modified token, unsupported schema, extra/wrong payload, old Summary token, wrong binding and cross-Grant substitution fail safely. Student Summary uses its canonical `student_session_summary_id` + `encounter_id` binding and rejects the frozen old binding even after rotation. Routine record/section binding remains independently authoritative; selected Evaluation never decrypts Intake.

`rotate_counselor_handoff_summary_encryption` verifies before rewrap; batch range 1–1000; normal rotation row-locks each batch; dry-run does not mutate. Existing rotation and new CONT-4 two-row/corrupt-batch tests verify multi-key recovery, exact counts-only output, primary-only read after rotation, repeat behavior and unchanged UUIDs/lifecycle/version/timestamps/Audit/Notification/delivery rows. A corrupt row remains unchanged and yields unsuccessful command status; other valid batches can commit. Diagnose/resume deliberately; rotation is not an envelope converter or all-or-nothing database restore.

## Consistent recovery unit

Recover schema + retained records + persisted identity policy + complete relevant old/new keys + backend image + frontend version + compatible worker/Beat/realtime consumers + secret source/mount definitions + broker/Notification/delivery claim state together. Preserve immutable Audit evidence, including old action names. Old keys may be required for historical backups even though they are not active runtime aliases.

Reversing `counseling.0004` drops the Handoff table and retained professional ciphertext. Disposable reversal tests prove that consequence; they do not make it a safe live rollback. Prefer a reviewed forward disable/provider withdrawal or authorized revocation that preserves ciphertext, protected custody and Audit. Provider withdrawal must use the exclusive database publication fence; absent genuine providers, no operational invalidation service is claimed. Real restore/cutover and any destructive rollback require separate authorization and a verified consistent recovery copy.
