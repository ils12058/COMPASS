## Confirmed scope to preserve

**TEAM-REPORTED OPERATIONAL PRACTICE:** request precedes payment; physical OR is presented at GCO; distinct receipt for every certificate; PHP 80 reported for both variants; external Registrar dry seal after issuance/printing.

**VERIFIED CODE FACT:** GSS prepares/records clerical facts, active authorized Counselor finally issues; Student history is owned; form/template/issuer snapshots and PDF release Audit exist; notifications and feedback invitation are existing issue side effects. See [source map](current-state-audit.md).

**PROPOSED DESIGN:** no PAID/DRY_SEALED state, no Cashier integration/payment processing, no new Registrar subsystem, no new print dialog, no unrelated eligibility/catalog/academic-record changes, no weakening of existing role fences.

## Handoff readiness

The architecture is specified enough to build and test GM-OR-1 in a separate PR using synthetic fixtures. Normalization/numbering approval and quarantine treatment are its earliest unresolved decisions. Real-data population cannot be represented as ready until the separate authorized inventory, writer fence and preservation checks exist. GM-OR-2 activation additionally requires the inspector grant matrix, approved fee applicability and pending-record transition policy. GM-OR-3/4 inherit those gates.

Open decisions are deliberate audit outputs; they do not justify changing runtime behavior in GM-OR-0 or asking for live credentials during this slice.
