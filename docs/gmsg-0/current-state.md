## 2. Encryption, keyring and rotation (`content.py`, ADR-105)

- `BODY_LIMIT = 4000`, `SCHEMA_VERSION = 1` (`content.py:10-11`).
- `validate_text` (14-24) rejects blank, oversized, NUL-containing and non-UTF-8 text; **no
  normalization** of line breaks or spacing, so the bound payload round-trips exactly.
- Keyring is `settings.GUIDANCE_MESSAGE_ENCRYPTION_KEYS`, parsed by
  `crypto.parse_fernet_keyring`; an invalid keyring raises `GuidanceMessageContentUnavailable`
  → HTTP 503 (`content.py:31-37`, `api.py:193-227`).
- **Authenticated binding** is a 4-field AAD: `guidance_thread_id`, `guidance_message_id`,
  `sequence`, `sender_id` (`content.py:40-46`), used by both `encrypt_body` (49-58) and `read_body`
  (61-76). **Verified consequence: a ciphertext cannot be moved between threads, senders or
  sequences, and re-keying a thread's identity fields is cryptographically impossible without
  re-encryption.**
- `read_body` also enforces `body_schema_version == 1` and the exact payload key set `{"body"}`
  (64-74) — historical decryption is "same schema, any keyring member", no dual-read branch exists.
- Rotation command `be/compass/guidance_messages/management/commands/rotate_guidance_message_encryption.py`
  (docstring: "Verify bound Message envelopes and rotate wrapping only (ADR-105)"): batched 1–1000
  (`:17-23`), `--dry-run` verifies without writing (`:19,46-47`), `select_for_update(of=("self",))`
  per batch when writing (`:47`), keyset pagination on `pk` (`:48-49,75`), verification through the
  real accessor (`:54`), re-wrap with `QuerySet.update` so **no business fact or timestamp moves**
  (`:64-71`), failures listed up to 20 then a `CommandError` leaving rows untouched (`:85-94`).
  **Not executed in GMSG-0** (management command; see `validation.md`).
