# Discovery and navigation

The current Student Home action opens `/portal/appointments/book`, where the existing flexible flow remains below a concise list of individual appointments, scheduled individual slots, and group activities. Each link leads to an existing transaction or section; My appointments and My Registrations remain separate. Direct routes and notification destinations are retained. No Student enters `/portal/services`.

The fixed picker searches server catalog pages and locally filters only that page; it explicitly says when the current page has no fixed-enabled Services and keeps Previous/More controls based on server pagination. A selected ID is read afresh through `servicesGet`, with active and fixed pathway checks. On confirmation it checks the Service and exact slot again; backend validation remains final. Search and pagination do not silently replace the selected Service. A stale or failed selected-Service read stops the slot panel and explains how to recover.

A selected Service that supports group sessions links to group discovery with `service_id`. That destination validates UUID shape, reads authorized current Service state, checks active/group configuration, and passes the exact ID to `groupSessionsDiscover`. Where both pathways are configured, it links back to fixed selection using the same UUID and restores the fixed-picker search/page when provided by that link. Invalid IDs are not sent as Service requests; changed or unreadable Services do not display filtered opportunities. The flexible link opens its normal discovery rather than assuming the existing paginated Appointment list can safely preselect a Service. Group event links from discovery use a controlled `from=discover` hint and optional validated UUID; direct notifications and history still return to My Registrations. The return link never accepts an arbitrary URL.

Event detail return retains the selected Service filter, but does not retain the earlier fixed-picker search/page after opening a particular event; the user can still return to that Service and search again. Flexible Service context is not transferred.
