# API contract assessment

Reused generated operations: `servicesList`, `servicesGet`, `servicesListBookableSlots`, `servicesBookSlot`, `appointmentsListBookingServices`, `appointmentsListEligibleCounselors`, `appointmentsListBookableSlots`, `appointmentsCreateMy`, `appointmentsListMy`, `groupSessionsDiscover`, `groupSessionsGetDetail`, `groupSessionsGetMyRegistrations`, `groupSessionsRegister`, and `groupSessionsCancelRegistration`. OpenAPI and backend schemas are unchanged; Orval is generated from the existing contract.

`servicesList` has server search and pagination but no arbitrary pathway filter. Fixed-slot selection filters each server page and labels page-local empty results honestly; no catalog-wide count or unbounded scan is claimed. This task-first approach does not require a new projection. A service-centered directory with global pathway filtering or authoritative availability counts would need a separate, evidenced contract and authorization review.

**Known contract gap:** `book_fixed_slot` invokes `_validate_inventory_prerequisite`, which can raise `AppointmentCurrentInventoryRequired` or `AppointmentCurrentAcademicYearNotConfigured`; `_raise_slot_error` in `be/compass/service_catalog/api.py` does not map these exceptions and falls through to generic `internal_error` 500. The frontend cannot distinguish such a refusal from an ambiguous committed response and therefore correctly reports uncertainty. A separately reviewed backend fix should map these to the existing typed Appointment error semantics and test both cases; this slice changes neither policy nor backend error contract.
