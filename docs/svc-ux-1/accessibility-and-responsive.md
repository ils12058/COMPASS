# Accessibility and responsive behavior

The pathway list uses shared Panel and ContextHelp, semantic headings and links, and an accessible existing confirmation dialog. It distinguishes loading, empty, invalid Service and failure states. Fixed and group confirmation retain exact selected identities; group registration now uses the shared consequential dialog. Success and uncertain results link to the applicable record/history. Source follows existing focus, text and responsive conventions; no claim of screen-reader certification follows from inspection.

Synthetic browser checks and exact widths/engines are recorded in [validation](validation.md). Manual screen-reader review, native browser zoom and institutional accessibility acceptance remain outstanding. CSS text scaling and keyboard automation do not substitute for those manual checks.
