# CONT-2B handoff and blockers

CONT-2A provides persisted intent/decision metadata and technical eligibility. No professional source is readable through a Grant. The source enum's finalized Evaluation projection is a prospective **reference**, not an implemented serializer/decryptor.

Before any operational activation:

1. Resolve D01–D05/D07/D10/D12/D13 with verified institutional decision documents, version, authorized decision makers, exact office/College scope, effective dates, maximum duration/advance, approved reasons, transfer/renewal/overlap and monitoring rules. Implement a reviewed policy provider; default None cannot be switched by an environment flag.
2. Confirm a viable independent approver for Head's own coverage and unexpected absence. Acting Head remains denied until formal delegation evidence/start/expiry/scope/revocation and capability binding are approved and enforced; existing overrides alone are insufficient.
3. Provision canonical capabilities through existing governed account processes after policy confirmation. No broad role defaults exist. Revalidate affected authentication state through established authority-change procedures.
4. Close the [documented synchronization gaps](concurrency-and-revocation.md), including all relevant capability/designation/role/organization writers and policy invalidation. Define/test the content-release linearization point. A Grant lock is insufficient proof.

CONT-2B must additionally resolve D06/D08 and relevant D13/D14/D18: exact source-category/field disclosure, Student transparency/consent or approved basis, source lifecycle/revision behavior, retention/monitoring and residual client persistence. Do not treat a technical APPROVED state or synthetic tests as institutional authorization.

Initial adapter candidates:

- Encounter: exact selected structural overview with a fixed, reviewed minimized serializer. No Student history listing, appointment token or new Context relationship.
- Routine: a source-owned selected finalized Evaluation adapter, with source Student/author/link/revision checks and only approved Evaluation fields. Never remove the Counselor filter from `get_assigned`; never include Intake or Inventory through convenience detail helpers.

Each read must reauthorize active canonical receiver + effective future-read capability + current approved policy + live interval + not-revoked Grant/version + exact selected source/projection + Student/lifecycle/affiliation + current owning-domain revision/lifecycle. Lock/recheck time and authority at the agreed release boundary and append a content-free read event atomically before returning a body. Denials precede decryptors. No serialized capability decision, bearer token, worker job or cached allow result is reusable authority.

Referrals and Follow-Ups are deferred. Their selection and disclosure boundaries require separately approved source-owned projections; grant reads cannot satisfy confidential Follow-Up manage/assignment predicates. Student Session Summary cross-author content, Intake/full Inventory, assessment results, media/transcripts, message bodies, credentials and exports remain excluded. Handoff document/keyring/editor and all request/approval/receiver UI belong to CONT-3, with separate encryption and audience. Notifications also remain absent until recipients/copy/channels/currentness are approved.

Retain ordinary Counselor assignment, College responsibility, appointment-provider, Routine authorship, Encounter ownership, Context defaults, source capabilities/revokes and E-Counseling custody. No permanent case transfer or historical reattribution follows from a temporary Grant. Browser expiry/cache-clearing and selected-source confidentiality tests belong to the slice that introduces actual UI/content reads; no backend-only metadata test proves their future behavior.
