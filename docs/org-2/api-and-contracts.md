# Catalog API and generated contract

All routes below are under `/api/v1/organization`, use existing session auth and strict schemas.
Mutations also require canonical CSRF and current recent MFA at API and protected service boundaries.
Existing list/detail/relationship operation IDs remain. CampusSummary, CollegeSummary and
ProgramSummary add required integer resource_version, including nested parents; other fields and
inactive-inclusive reference semantics remain. Consumers must regenerate from OpenAPI.

| Method/path | Operation ID |
|---|---|
| POST /campuses | organizationCreateCampus |
| POST /colleges | organizationCreateCollege |
| POST /programs | organizationCreateProgram |
| PUT /campuses/{target_id}/name | organizationRenameCampus |
| PUT /colleges/{target_id}/name | organizationRenameCollege |
| PUT /programs/{target_id}/name | organizationRenameProgram |
| PUT /campuses/{target_id}/active | organizationSetCampusActive |
| PUT /colleges/{target_id}/active | organizationSetCollegeActive |
| PUT /programs/{target_id}/active | organizationSetProgramActive |
| PUT /programs/{target_id}/policy | organizationUpdateProgramPolicy |
| GET /campuses/{target_id}/impact | organizationGetCampusImpact |
| GET /colleges/{target_id}/impact | organizationGetCollegeImpact |
| GET /programs/{target_id}/impact | organizationGetProgramImpact |
| GET /campuses/{target_id}/history | organizationGetCampusHistory |
| GET /colleges/{target_id}/history | organizationGetCollegeHistory |
| GET /programs/{target_id}/history | organizationGetProgramHistory |

Creation requires code/name/is_active/basis and parent UUID for College/Program. Program creation
also requires all policy fields, including explicit nullable values. Rename requires name/basis/
expected_resource_version. Status requires is_active/basis/version. Policy requires the whole
classification/status/levels representation plus basis/version. Versions and policy levels use
strict integers; status uses strict Boolean. Extra fields, including code/parent transfers,
mfa_verified and can_deactivate, are validation errors. No arbitrary PATCH, DELETE, enable/disable
legacy routes, transfer/merge or generic model serializer is introduced. Success uses existing 200
conventions and the persisted summary. History uses page/page_size/has_next; impact is aggregate-only.

| HTTP | Stable error code / semantics |
|---|---|
| 401 | Existing session authentication errors |
| 403 | permission_denied; invalid_session; mfa_setup_required; recent_mfa_required |
| 404 | catalog_not_found |
| 409 | catalog_duplicate_code; catalog_stale_version; catalog_inactive_parent |
| 409 | catalog_deactivation_blocked, with safe blocker code/count details |
| 409 | catalog_policy_approval_required; catalog_pending_f4_policy_decision_required |
| 409 | catalog_not_initialized; catalog_busy for deadlock/lock timeout/cancel contention |
| 422 | invalid_catalog_request or canonical request/schema validation error |

Errors retain the common error envelope/request correlation. No raw SQL error or private dependent
record ID is returned. A conflict requires reload/review and deliberate resubmission, not automatic
retry. The impact timestamp/version does not authorize the eventual mutation.

[OpenAPI](../../contracts/openapi.json) is generated by export_openapi; tests pin all 16 IDs, strict
inputs, required versions, safe impact shape and preserved IDs. Orval generates ignored clients
through [fe/orval.config.ts](../../fe/orval.config.ts); generated files are not hand-edited/committed.
The current frontend compiles without source changes and receives no catalog management UI in ORG-2.
See [validation](validation.md) for executed Orval/typecheck/lint/build evidence.
