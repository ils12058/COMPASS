# Follow-ups and boundaries

## Institutional decisions

GCO/UCN must approve the exact external disclosure bundle before activation:
Service labels, schedules, current assigned provider names for Students, permitted
staff context, mailbox/privacy expectations and cancellation messaging. Student
identity in staff email and previous-provider names are deliberately absent from
version 1. Broadening recipient classes or fields requires a new reviewed policy
version; Notification ownership alone is never authority. No approval is inferred
from Proposal #5 or these synthetic previews.

## NOTIF-03 operational expansion

Audit Group Sessions, Good Moral, Call Slips and other future operational events
independently. Reuse the validated origin, closed target routes, typed plan and
final equality; define source-owned facts, exact event provenance, field/recipient
policy and legacy fallbacks for each family. Do not extend the Appointment bundle
or generic payload storage to infer another domain's authority. Reference these
seven-event outcomes and institutional decisions as dependencies; no future event
family was implemented here.

## NOTIF-04 cross-channel validation

Extend coordinated coverage for approved email, Notification Center, Push and
authenticated desktop/mobile login/MFA/record access. Preserve historical in-app
utility when rich external mail suppresses an obsolete event. The current change
already verifies Push/realtime regressions and unchanged reminder semantics;
full cross-channel UX/client testing remains separate.

  monitoring under an authorized rollout. No live proof is supplied by local tests.

## Provenance limits requiring separate review if expanded

Scheduled sources have no independently frozen original schedule/provider. This
implementation enriches only verified unchanged initial state and otherwise keeps
qualified generic links. Historic names are current display values, explicitly
labeled. Reminder sources retain revision/start, not a full content snapshot.
Reassignment sources do not snapshot schedules; only latest unambiguous changes
can use verified current context. Timestamp ties/conflicts suppress conservatively.

Supported services maintain revision/change history; arbitrary out-of-band database
edits are not immutable provenance. A future requirement to deliver historical
events after later mutations would need explicit historic wording, institutional
approval and narrowly owned snapshots/revisions with retention/migration analysis.
No such schema, backfill or generic Notification JSON store is justified here.
