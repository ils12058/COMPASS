# Concurrency, durable replay and Audit

The request row is the serial decision fence, matching GM-OR-1. A control-row shared lock excludes the existing exclusive import transition; existing identity locks precede assignment row locks, then inspection rows. Acting-account locks fence normal authority changes. Active F4 issuance acquires the Counselor and Student rows together in ascending UUID order, matching account management actor/target locks; it then retains the existing Student CURRENT validation. Inspection does not introduce a Student lock; final F4 issuance keeps the existing Student CURRENT lock after request/receipt validation. No lock order is reversed within GM-OR-1 correction paths. Privileged direct writers remain outside actor-specific service authority.

A unique verification operation UUID binds actor/request/reviewed resource/revision/method using SHA-256. Exact replay is checked before stale/terminal rejection after fresh authority/mode checks. Changed intent conflicts; it never moves or revives evidence. Same-request operations serialize, with one active verification index as database authority. Cross-request global operation races use a savepoint and only the named operation uniqueness error becomes the safe idempotency conflict; the losing transaction's request changes/Audit disappear.

Tests use independent PostgreSQL connections with barriers and events, not SQLite. They inspect committed verifications, assignments, lifecycle, policy snapshots, actor/time and Audit: correction versus inspection, inspection versus preparation/issuance/cancellation in both orders, simultaneous fresh inspections, identical replay, conflicting operation reuse across requests, late correction versus final issuance, revocation/deactivation before and after account fencing, policy loss during each mutation, and legal DORMANT→FENCED versus inspection. Existing GM-OR-1 same-key/replacement/import/timeout races remain registered.

New events: `good_moral.receipt_verified`, `good_moral.receipt_verification_invalidated`. Metadata contains only exact revision/verification references, policy identity/version, method or controlled reason. No raw OR, amount, Student identity or arbitrary payment narrative is copied into generic Audit, notifications, telemetry or hints. Existing preparation/return/correction/cancellation/issue events remain. Synchronous Audit failure rolls back inspection, invalidation, projection/lifecycle, and associated issuance side effects.

There are no new receipt emails or notifications. Existing issuance notification and feedback opportunity remain idempotent and transactionally associated with issuance. Browser uncertainty refreshes current saved state without automatic resubmission. A frozen confirmation now submits reviewed request/revision/inspection tokens alongside preparation version.

Limits: database-owner trigger disabling/truncation, unsupported direct account-policy writers, multi-process mixed-policy deployment, actual production volume and native physical inspection are not proved by these tests. The code-owned provider is immutable within an ordinary deployed process; approved schedule changes require a coordinated writer drain. Final fresh capability/fee checks mitigate supported races but do not turn external arbitrary policy writers into a serializable registry.
