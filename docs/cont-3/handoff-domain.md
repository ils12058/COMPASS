# Confidential Counselor Handoff domain

`counseling.CounselorHandoffSummary` is an independent professional resource. One protected OneToOne Grant, protected Student/author/receiving-Counselor references, UUID, ciphertext, DRAFT/SUBMITTED state, server submission time, positive optimistic version and creation/update timestamps. No Student publication field, audience switch or copied Evaluation store exists. Acknowledgment actor/time and correction histories are deferred until their procedures are approved.

Additive migration `counseling.0004_counselor_handoff_summary`, after CONT-2A `0003`, is registered in `canonical_migrations.json`. Existing canonical hashes, CONT-1B/2A migrations and source models remain unchanged. Database constraints enforce one Handoff per Grant, present ciphertext, positive version, state/submission pairing and author distinct from recipient. Cross-row Grant/Student/author/receiver consistency is independently validated on every service operation; API inputs cannot supply or change those identities. Protected FKs preserve historical references.

## Policy and audience

A separate immutable `ApprovedCoverageWorkflowPolicy` requires opaque evidence for selection, author qualification, Handoff disclosure basis, retention and client safety; exact Colleges; finite dates; explicit office cases and source kinds. Its only supported author rule is ACTIVE_ORIGINAL_ONLY, post-expiry rule DENY_ALL, acknowledgment/notification rules DEFERRED. Unsupported assumptions deny. Its full digest is bound into the operational policy and existing Grant snapshot. Changing evidence, identities, rules or dates requires a new request/approval. A shaped evidence reference is not institutional sign-off; default provider returns None.

Two explicit capabilities have **no role/designation defaults**: `counseling.handoff.manage_own` requires continuity metadata and ordinary Counseling read prerequisites; `counseling.handoff.read_received` requires selected-read eligibility. Active canonical Counselor identity, exact relationships and real policy are independently required. Student/GSS/IT/officer/unrelated Counselor and Head-as-approver-only cannot obtain bodies through unusual overrides.

The original qualified author may create/read/update a draft while the sealed Grant is REQUESTED or valid APPROVED (including scheduled), before expiry. Author capability, current Student/office conditions and recipient qualification are rechecked. Receiver reads require exact recipient, live approved Grant with `starts_at <= now < expires_at`, current approval authority, receiver capability, submitted state, session and valid identity binding. Author submitted reads use the same finite author boundary; there is no permanent post-expiry author exception. Draft existence/status are author-only; other metadata readers see no draft.

## Lifecycle and release

Create uses absent Handoff version zero; draft changes require the exact current Handoff and Grant versions and increment Handoff version once. Content is bounded to 12,000 Unicode characters, preserves whitespace, and rejects NUL/unencodable values. Empty drafts may be saved; submission requires valid non-whitespace content. Submission is server-timed and immutable. A repeated submit with its original pre-submit version or current submitted version returns metadata without another mutation/event, after full current authorization. Other stale versions deny. There is no post-submission edit, correction, publication or deletion API.

Every operation runs inside an outermost durable PostgreSQL READ COMMITTED transaction: shared policy fence → ordered relevant User rows → exact Grant/Scope NOWAIT → existing ten authority SHARE NOWAIT fences → current HTTP session NOWAIT → Handoff NOWAIT. Authority is refreshed after lock acquisition. Non-metadata operations filter guessed Grants to exact author/receiver before locking. Busy locks yield bounded conflicts without internal retries. A one-second transaction-local timeout bounds waiting locks/Audit insertion. Decrypt only after identity/policy/Grant/document checks, and recheck after projection and synchronous Audit. The final post-Audit check is the authorization linearization point; commit precedes returning a body. Audit failure or expiry rolls back prepared content and mutations/events. Submitted content is never copied to Grant/Scope.

Supported PostgreSQL DML paths serialize against the established User/authority/Grant/Handoff locks. Rotation locks Handoff rows and preserves business metadata; reads conflict safely if it holds the row first. Future policy providers must publish/invalidate under the same exclusive advisory fence with authoritative transactionally visible storage. Privileged schema/SQL rewriting, fabricated evidence, stale external provider caches and mixed-version deployments are not proven safe. Default providers continue denying; these are activation blockers, not exceptions. Already authorized responses may arrive after commit/revocation and cannot be recalled.
