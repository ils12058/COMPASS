# Frontend confidentiality and accessible behavior

Routes `/portal/counseling/coverage` and `/coverage/[grantId]` use existing portal session, generated Orval operations, TanStack Query, PageHeader/Panel/Button/form controls, Context Help and consequential dialogs. Counseling has one Case coverage entry and an author-owned Encounter contextual request action. No Student route or full history viewer is added. Philippine-time inputs and institutional date formatting remain explicit; backend time/status is authoritative.

Selected source and Handoff bodies are transient protected queries. Keys include confirmed account, Grant, expected Grant version, source/Handoff identity and local authorization generation plus canonical generated query key. The detail root also remounts on session/role/capability identity changes. `gcTime:0`, no automatic retry, zero stale time, focus/reconnect rechecks and 15-second active-query revalidation are scoped to coverage. No local/session storage, IndexedDB, persisted Query cache, service-worker cache, URL, telemetry or error payload contains body text. Existing same-origin API transport and CSRF remain authoritative.

A per-view cancellation generation rejects obsolete async completions after clearing. It is not a permission token or separate server-state store. Clear on Grant/policy known expiry, backend denial/conflict/failed protected refresh, session revalidation, account/role/capability/session change, offline and hidden tab. Cancel/remove protected queries and unmount editors/viewers. Explicit **Check access again** fetches current Grant and workflow configuration; it never replays a mutation or silently resurrects an old body. A new record open still calls the protected backend adapter. Routine omitted fields produce no placeholder; approved null ratings show Not rated and empty text shows No text recorded.

Same-origin `BroadcastChannel("compass-case-coverage")` sends **only Grant UUID invalidation hints** after decisions; another tab clears immediately on that hint. It cannot authorize, submit or extend a Grant. Unsupported/remote changes rely on backend checks at the next request and bounded polling, not an instantaneous remote recall guarantee. Background/offline tabs clear and require a deliberate confirmed check. Session logout/account switches retain the existing portal/account ownership and session-revalidation mechanisms. A response authorized before revocation can arrive later; a locally invalidated generation cannot repopulate it.

Normal observer cancellation (including React development effect replay) does not itself revoke the current generation. This is distinct from a protected server denial. Tests exercise both ordinary cancellation and late responses following authority loss.

The Handoff editor preserves exact text and current saved version. Background refresh does not replace unsaved text; a changed saved version disables consequential writes and requires deliberate review/load. Local close and navigation have unsaved-change handling. Submission confirmation identifies recipient and explains immutability and no Student publication. No draft body is fetched by approvers or receivers. A confirmation pins its reviewed Grant version. Background version changes close it; neither a refresh nor a 409 silently rebases the confirmed action. A stale own-draft write preserves unsaved text while an independently authorized draft read loads the saved version for deliberate review. Authority-denied reads still clear the editor.

Browser validation covers labeled controls, meaningful confirmations, keyboard activation/Escape/cancellation/return focus, mobile portrait, desktop, 200% CSS zoom and long wrapping. This is automated synthetic interaction evidence, not screen-reader certification, real-device testing or institutional UAT. See executed results in validation.md.
