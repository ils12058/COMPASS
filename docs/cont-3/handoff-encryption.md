# Handoff encryption and key custody

The dedicated ordered ring is `COUNSELOR_HANDOFF_SUMMARY_ENCRYPTION_KEYS`; protected-file contract `COUNSELOR_HANDOFF_SUMMARY_ENCRYPTION_KEYS_FILE`; source `counselor_handoff_summary_encryption_keys`. The first key encrypts, all configured keys decrypt. `handoff_content.py` uses existing `confidential_data.crypto` authenticated versioned JSON/Fernet mechanics, not a generic messaging adapter. Schema version 1 binds Handoff UUID, Grant UUID, Student UUID, author UUID and receiving-Counselor UUID. Payload is exactly `{content}`. Every read validates exact bindings/payload/text; submitted empty bodies deny. Student Summary and Routine tokens cannot be accepted as Handoffs.

Settings allow an absent ring at process startup so an inert feature does not require invented live provisioning. All body reads/writes fail safely without valid keys. Supplied invalid/duplicate keys fail configuration validation. Reuse is rejected against SECRET_KEY, TOTP, Push storage, Routine, Student Session Summary, Referral, Exit Interview, Inventory, Graduate Tracer, Account Profile, Feedback, Guidance Messages, Assessment and Follow-Up rings. Tests use ephemeral synthetic keys only. No live secret inventory or value was read.

Updated contracts: Django settings and test bootstrap; `be/.env.example`; runtime inventory, `_FILE` example and metadata-only preflight; staging Compose; runtime/Compose tests and runtime-secrets documentation. The new source is mounted **only in web**. Worker/Beat explicitly clear direct and `_FILE` settings and receive no Handoff mount. They do not decrypt Handoffs for notifications, counts or scheduling. Local Compose remains environment-driven. The file validator requires the declared file/pointer/owner/mode even when its optional contents are empty; deployment therefore needs separately authorized file preparation before the changed staging manifest can start.

`rotate_counselor_handoff_summary_encryption` verifies every binding/payload before rewrapping to the primary key. Supports `--dry-run` and batches 1–1000, preserves Fernet time and all business timestamps/state/version/Audit/Notification, leaves unreadable rows unchanged and exits unsuccessfully with counts-only output. Normal reads and rotation coordinate through the same Handoff row lock. It does not convert old Summary envelopes, change relationships or invent missing keys. Rotation itself requires separately authorized custody and maintenance planning.

Before deployment: verify independent custody/recovery, provision the web-only file through the authorized operator, verify pointer permissions/separation and secret-readiness checks without printing values, rehearse retained ciphertext recovery/rotation, apply the additive migration with coordinated consumers, deploy the exact backend/frontend contracts and verify policy providers separately. No live key generation/provisioning, SSH, migration, reset or deployment is authorized by this PR.
