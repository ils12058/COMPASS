# CONT-3 readiness and institutional gates

Two tested read-only source adapters and canonical generated contracts now exist. Their runtime default is **denied**, and they do not constitute institutional activation readiness. CONT-3 must not fabricate operational screens that imply these sources are already approved for use.

## Governance before activation

Resolve [CONT-0 decisions](../cont-0/institutional-decisions.md) with real versioned evidence and authorized decision makers:

- D01–D05: legitimate requester/office scope; independent approval and backup/delegation; finite duration/advance/renewal; permitted source-metadata selection procedure. No general history enumerator or Acting Head route currently exists.
- D06–D08: exact category/projection/field inventory and operational reason/evidence categories; approved disclosure basis and Student transparency/consent procedure. Evaluation ratings and three narrative fields are not all implicitly approved.
- D09/D10: legitimate urgent absence procedure without break-glass/self-approval, and Student transfer/lifecycle rules.
- D11–D15: Handoff author/audience/submission/correction/post-expiry rules, overlap/receipt, audit inspection/monitoring, retention/access-request procedures and exact notification recipients/channels/currentness.
- D16/D17 where relevant: retained-versus-disposable environment classification and existing Summary cutover obligations; independent Handoff key custody/provisioning/recovery. No reset or new key is authorized by these code changes.
- D18: client clearing, training/accountability and residual previously viewed content.

Implement/review real operational and disclosure providers using authoritative transactionally visible state, verified evidence and the tested exclusive publication/invalidation fence. Do not use environment booleans, label-only evidence, stale provider caches or technical overrides as sign-off. Bind the complete disclosure digest into a **new** operational request/approval; old metadata-only grants cannot silently acquire content access. Verify mixed-consumer/schema/key release coordination and production contention/role permissions separately. Default providers remain None until that separately authorized work is complete.

## Planned and unexpected coverage

Planned workflow can select the original author's own exact sources, request finite coverage and seek independent approval. Unexpected absence must use an approved metadata-selection/records-custodian procedure and a viable independent approver; it need not require the absent original Counselor's login or a Handoff body. A Head requesting/receiving needs a separate legitimate approver. Expiring capability overrides do not model formal Acting Head delegation; that route remains unavailable until approved evidence/scope/revocation rules are implemented.

Existing CONT-2A request/decision APIs are metadata only. CONT-3's approval interface must not fetch professional body routes merely because it has a source UUID or Head designation. Receiver review calls one exact selected source with current expected Grant version; changed scope/revision, denied authority or unconfirmed policy requires deliberate recovery, never silent reapproval or automatic retry. Grants do not create ordinary Encounter/Routine ownership, Context relationships, Appointment reassignment or Follow-Up management authority.

## Receiving UI and client contract

Use generated operations `counselingContinuityGetSelectedEncounterMetadata` and `counselingContinuityGetSelectedRoutineEvaluation`. Query identity must include account, Grant, source and expected version. All server authority remains backend-derived; ACTIVE metadata and realtime hints are not permission tokens.

The Evaluation object includes only approved fields. Distinguish an omitted unapproved key from an approved null rating; do not insert zeros, empty strings or hidden-field placeholders that imply source values. Preserve safe author/provenance attribution through separately approved metadata, not general Routine detail, Intake or a new history viewer.

Clear protected memory on expiry/revoke, 401/403/404, failed reauthorization and account changes; gate stale in-flight responses by authority generation. No persistent browser storage or API/service-worker cache. Handle bounded 409 source/authority conflicts without automatic consequential replay. Do not promise recall of previously viewed information. Real backend tests here do not replace CONT-3's required UI, accessibility, phone/desktop, offline, multi-tab and late-response tests.

## Confidential Handoff and notices

A Counselor Handoff Summary remains a separate future encrypted authored resource with Grant/Student/author/recipient binding, dedicated keyring, submission immutability and approved correction/retention rules. Do not repurpose Student Session Summary publication, audience flags or Evaluation storage. No model, editor, key provisioning, Handoff body or notification placeholder is implemented here.

Student notices/consent and any in-app/email/Push/realtime updates require approved recipients, safe copy, basis and currentness. No professional narrative, Student concern, score or source excerpt belongs in those channels. Referrals, Follow-Ups, full Intake/Inventory/Support, assessments, Summary cross-author content, media/transcripts, messages, credentials and exports remain excluded from continuity until separate source-specific approval and implementation.
