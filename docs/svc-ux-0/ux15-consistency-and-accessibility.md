# UX15 consistency and accessibility

**VERIFIED by source:** Existing screens use shared headings, panels, notices, labelled fields, status messages, local navigation, help, dialogs and focus styles. Flexible booking has step headings, loading/error states and a deliberate review ([booking](../../fe/src/features/appointments/appointment-booking-page.tsx#L345)); fixed slots use labelled search/select and a confirmation dialog ([picker](../../fe/src/features/appointments/appointment-fixed-date-booking.tsx#L30), [panel](../../fe/src/features/services/service-fixed-slots-panel.tsx#L543)); group discovery exposes eligibility and loading/failure/empty states ([panel](../../fe/src/features/services/service-group-sessions-panel.tsx#L1354)); Services has search, filter, status, help, and consequence-review patterns ([list](../../fe/src/features/services/services-list-page.tsx#L174), [editor](../../fe/src/features/services/service-editor-page.tsx#L807)). Responsive grids and wrapping exist, but source inspection is not proof of full usability or accessibility.

| Area | Assessment and proposed validation |
| --- | --- |
| Heading and actions | Names differ between “regular,” “scheduled,” and “fixed”; explain pathway in page context. Compare Home, local navigation and detail back links. |
| Search and filters | Fixed and staff group pickers filter the current fetched catalog page after pagination; an empty page does not mean no matching Service exists across all pages. Copy acknowledges page scope. Exercise search and next/previous; do not silently treat a page as the entire catalog. |
| Loading, stale data and errors | Flexible slot queries have freshness, selection dropping and submit recheck ([freshness](../../fe/src/features/appointments/appointment-slot-freshness.ts)); fixed/group handlers do not show the same explicit stale/uncertain recovery. Do not convert a failed refresh into “no availability.” Verify race and error paths with server responses. |
| Pending and completion | Flexible submit has intent/replay handling and a completion dialog. Fixed uses a confirmation dialog and pending state; group uses a per-session pending action and notice. Provide clear, accessible, domain-appropriate outcome and history links, preserving the current intentional confirmation behavior. |
| Small screens and keyboard | Grid breakpoints, native controls and focus styles are present; **TESTED** coverage is only that recorded in [validation](validation.md). Later work must test keyboard order, dialogs, focus after completion/error, 320px and zoom. A source check is not a screen-reader or native-zoom test. |
| Contextual Help | [Service Help](../../fe/src/features/services/service-help.tsx) explains provider coverage and online Counseling; group workspace has its own Help. Align terms and avoid suggesting video readiness from a configured mode. |

**PROPOSED:** follow [frontend rules](../../fe/AGENTS.md): reuse existing components, generated contracts and per-domain freshness; preserve unsaved input and backend errors; never automatically replay a consequential mutation. Run focused Chromium/WebKit synthetic flows and manual keyboard, screen-reader and native zoom checks before claiming accessibility readiness.
