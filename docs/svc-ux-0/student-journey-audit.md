# Student journey audit

## Actual paths

**VERIFIED by source:** Home's primary action is “Book appointment” for current Students with `appointments.manage_self` ([overview](../../fe/src/features/portal/home/overview-presentation.ts#L145), [access](../../fe/src/features/appointments/appointments-access.ts#L12)). It opens flexible booking: search appointment Services, select one, mode, Counselor, date/time, review and book ([booking](../../fe/src/features/appointments/appointment-booking-page.tsx#L345)). A “Scheduled slots” action opens `?pathway=FIXED_DATE_SLOT`; its separate searchable Service picker filters each fetched catalog page locally, then opens available slots ([picker](../../fe/src/features/appointments/appointment-fixed-date-booking.tsx#L20)). Flexible selection shows description and any Inventory requirement; fixed selection is a select control, with actual slot list and confirmation after selection. No guarantee of a slot follows pathway configuration.

The sidebar separately offers Group Sessions to Students with `appointments.view_self` ([workspace](../../fe/src/features/portal/components/portal-workspaces.ts#L128), [access](../../fe/src/features/group-sessions/group-sessions-access.ts#L5)). Its index routes to discovery, showing published sessions and server-derived registration eligibility; registration is submitted directly from the list, and cancellation uses a confirmation dialog ([panel](../../fe/src/features/services/service-group-sessions-panel.tsx#L1286)). Event details are readable but do not themselves offer the registration action; their Student back link always points to My Registrations, even if entered from Browse Sessions ([detail](../../fe/src/features/group-sessions/group-session-detail-page.tsx#L71)). This is a navigation friction finding, not an assertion that the route fails. A Student's [Services layout gate](../../fe/src/app/%28portal%29/portal/services/layout.tsx) denies the staff management workspace even though active catalog reads are permitted; embedded Student panels in Service detail are therefore not a general Student discovery route.

Successful flexible booking displays a completion dialog linking to the Appointment; fixed booking displays a reference and link; group registration displays a success notice and refreshes discovery and My Registrations. Appointment and registration history remain separate ([fixed](../../fe/src/features/services/service-fixed-slots-panel.tsx#L451), [group](../../fe/src/features/services/service-group-sessions-panel.tsx#L1313), [history](../../fe/src/features/group-sessions/group-sessions-history-page.tsx)). Notifications target Appointment or Group Session details ([targets](../../fe/src/features/notifications/notification-targets.ts#L46)). My actions is a task queue, not a complete booking history ([page](../../fe/src/features/student-actions/student-actions-page.tsx#L34)).

## Student questions

| Question | Current answer / limitation |
| --- | --- |
| What Service do I need? | Flexible search provides names/descriptions, but there is no common Student-facing service overview spanning all three pathways. Group discovery is event-led. |
| Is it available? | Configuration, Counselor availability, published slots and registration capacity are different; no single page answers all of them. Empty flexible list is configuration/provider filtered, not proof of times. |
| Individual, fixed or group? | Individual booking offers the scheduled-slot link; Group Sessions is a separate destination. The difference between a private individual appointment and registering for a group is not presented together. |
| Online or in person? | Flexible mode selection, fixed slot cards, and group event cards each show mode; these are opportunity-specific. |
| Inventory? | Flexible choice/review identifies the flag. Fixed confirmation does not explain it before submission, even though the backend checks it when set. Group registration has no such check. |
| What next and where? | Success feedback links to individual records for appointments; group shows a status and has separate My Registrations navigation. Registration history and direct event access remain available after configuration changes, subject to backend scope. |

**PROPOSED:** retain existing pathways and make their meaning and cross-links visible where a Student decides; preserve service context only where supported by verified API contracts. Do not present an enabled flag as a live opportunity. Avoid requiring Students to enter the admin workspace. Resolve event-detail return context and post-action navigation. Verify actual runtime behavior with synthetic browser scenarios before changing it.
