# Authorization and cross-domain safety

## Role boundaries

**VERIFIED:** [Policy grants](../../be/compass/accounts/policy.py#L585) are defaults; actual capabilities can be changed. Backend checks current identity, capability and resource scope; UI hints do not grant authority.

| Actor | Relevant actual boundary |
| --- | --- |
| Student | Active catalog read with `services.catalog.view`; own appointments with self capabilities; new bookings/registrations require current Student lifecycle. Group discovery/history requires `appointments.view_self`, mutation requires `appointments.manage_self`; cancellation has its own lifecycle conditions. [Appointment](../../be/compass/appointments/api.py#L351), [group](../../be/compass/group_sessions/api.py#L237), [fixed](../../be/compass/service_catalog/api.py#L638). |
| Counselor | Default catalog view and appointment management; individual provider qualification is Service-specific. Fixed slots scoped to self; group scope follows organization/facilitation. Appointment managed record scope is separate. [Slot access](../../be/compass/service_catalog/access.py#L18), [group](../../be/compass/group_sessions/access.py#L100), [appointments](../../be/compass/appointments/access.py). |
| Head Guidance Counselor | Designation adds `services.manage` and other explicit capabilities, while role remains Counselor. It does not add blanket slot/group resource access or confidential Counseling access. [Policy](../../be/compass/accounts/policy.py#L705). |
| Guidance Services Staff | Default appointment management, catalog view, and active direct supervision needed for fixed/group staff authority; scoped to supervisor or organized/assigned session as applicable. Not a Counselor provider. [Slot access](../../be/compass/service_catalog/access.py#L18), [group access](../../be/compass/group_sessions/access.py#L27). |
| IT Administrator | Default Service catalog/manage and office availability authority; no automatic Counselor or group operational authority. Catalog mutations require recent MFA. [API](../../be/compass/service_catalog/api.py#L435). |
| Other authorized catalog viewers/managers | Active catalog reads require `services.catalog.view`; inactive inclusion and reads require `services.manage`. The frontend Services workspace currently requires both even for a catalog viewer. That is the documented administration boundary, not proof every viewer is authorized to manage. [API](../../be/compass/service_catalog/api.py#L397), [frontend](../../fe/src/features/services/services-access.ts#L8). |

**VERIFIED:** The fixed-slot UI gate prevents default scoped operators from reaching a backend-authorized panel; it is an unnecessary frontend dependency for that operational task, not evidence that an unscoped provider may be managed. Group workspace has its own route. Student read capability alone does not grant mutation; do not expose registration as authorized solely from `appointments.view_self`.

## Safeguards and UX checks

| Risk | Backend authority / frontend role |
| --- | --- |
| Duplicate flexible Appointment | API requires an idempotency key and replay handling ([API](../../be/compass/appointments/api.py#L760)); frontend preserves intent key on uncertain outcomes ([page](../../fe/src/features/appointments/appointment-booking-page.tsx#L165)). Preserve this contract and deliberate retry. |
| Duplicate fixed booking / registration | Fixed slot locks and checks booked state before creating an Appointment ([fixed](../../be/compass/service_catalog/fixed_slots_services.py#L553)); Group locks, checks registration/capacity and has an active-registration uniqueness constraint ([group](../../be/compass/group_sessions/services.py#L1030), [model](../../be/compass/group_sessions/models.py#L216)). These are not the flexible API's replay-success contract; uncertain responses need status reconciliation, not blind replay or an invented key. |
| Stale offering, invented availability, conflicts | Backend rechecks current state, qualification, windows and conflicts during mutations; flexible UI additionally rechecks and removes stale choices. Fixed/group UI pending controls are usability measures, not guarantees. [Scheduling](../../be/compass/service_catalog/scheduling.py#L54), [flexible UI](../../fe/src/features/appointments/appointment-booking-page.tsx#L243). |
| Provider qualification / Student lifecycle / Inventory | Backend resolves current Counselor qualification and current Student; Inventory is checked for applicable individual bookings only. Group facilitator status is not qualification. [Appointment](../../be/compass/appointments/services.py#L566), [fixed](../../be/compass/service_catalog/fixed_slots_services.py#L619), [group](../../be/compass/group_sessions/services.py#L1030). |
| Configuration changes and historic records | Transactional consequence review and acknowledged change do not rewrite commitments; saved Appointment provenance and group attendance remain. [Catalog](../../be/compass/service_catalog/services.py#L568), [ADR-089](../../be/docs/decisions/ADR-089-service-catalog-consolidation-and-counselor-qualification.md). |
| Cancel, withdraw, reschedule | Individual cutoff, status, lifecycle and online-room restrictions are backend owned. Group cancellation/withdrawal use different lifecycle rules; Student registration cancellation is separate. [Appointments](../../be/compass/appointments/services.py#L1042), [groups](../../be/compass/group_sessions/services.py#L884). |
| Confidential records and online Counseling | Appointment access is relationship/scope checked; group resource access distinguishes organizer, supervisor and facilitator. Appointment-backed Counseling/E-Counseling uses saved provenance and separate gates; no Catalog redesign may broaden it. [Appointment access](../../be/compass/appointments/access.py), [group access](../../be/compass/group_sessions/access.py#L100), [ADR-024](../../be/docs/decisions/ADR-024-ecounseling-daily.md). |

**PROPOSED:** after an uncertain fixed/group response, query the authorized current record/history, explain whether the result can be confirmed, and require a deliberate next action. Preserve dialogs where present and do not silently replay mutations. Confirm the recoverability of each response and endpoint before implementing; absence of a visible result is not proof of failure.
