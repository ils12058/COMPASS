## Findings and direction

1. **VERIFIED — Keep the domain boundaries.** Flexible booking and fixed slots create canonical Appointments; group registration and attendance remain separate. Booking flags express configuration, not a promise that a time or seat is available. See [pathways](current-state-and-pathways.md).
2. **VERIFIED — Discovery is fragmented.** Student Home leads to flexible booking; scheduled slots are a secondary link there, and Group Sessions have a separate sidebar workspace. The Services workspace intentionally requires catalog management. A Student cannot use that workspace as a unified service directory. [Journey](student-journey-audit.md).
3. **VERIFIED — A staff access mismatch deserves priority.** The only fixed-slot staff panel is under the Service layout, which requires both `services.manage` and `services.catalog.view`; default Counselors and supervised Guidance Services Staff have scoped slot authority but no `services.manage`. The panel's own role gate does not override the enclosing layout. This is a frontend entry-point issue, not authority to widen backend access. [Staff audit](staff-workflow-audit.md).
4. **VERIFIED — Service list and editor privilege flexible booking in their labels.** The editor calls other pathways “Additional” and “future”; the list filters and summarizes only appointment booking. Detail already states that enabling a pathway does not publish an opportunity, although some status language can still overpromise. [Copy](navigation-and-usercopy.md).
5. **VERIFIED — Recovery differs across pathways.** Flexible booking rechecks time and preserves an idempotency key for uncertain requests. Fixed-slot confirmation and group registration have pending controls and server safeguards but lack the same explicit uncertain-result reconciliation in the inspected handlers. Do not assume the flexible endpoint's replay contract exists for the other mutations. [Safety](authorization-and-safety.md).
6. **VERIFIED — Inventory configuration has a non-obvious constraint.** The flag is cleared when flexible booking is turned off, yet the fixed-slot booking service also checks it when set. A fixed-only Service therefore cannot configure this requirement through the current model. Group registration does not apply this Inventory check. Policy changes require a separate decision; do not imply a universal prerequisite. [Pathways](current-state-and-pathways.md).

**PROPOSED:** connect existing pathway-specific experiences with a lightweight Student service-centered discovery layer and contextual links, subject to evidence about data and eligibility. Preserve independent histories, actions, and backend contracts. Add a scoped fixed-slot operational entry point for authorized staff. Improve administration wording and hierarchy without confusing configuration with a published offering. No universal wizard or separate booking subsystem is justified. [Implementation slices](implementation-plan.md) and [open decisions](open-decisions.md).
