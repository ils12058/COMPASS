## 3. CSV contract

Exact headers in any order: `institutional_id,campus_code,college_code`.

- All three headers are required; duplicates, missing headers and any unknown header (for example
  `program_code`, `email`, `enrollment_status`, `graduation_date`) raise
  `RosterImportUnsupportedHeaders`.
- Decode with `utf-8-sig` in strict mode; invalid UTF-8, NUL characters, an empty file, a
  header-only file and malformed quoting raise `RosterImportMalformed`.
- Limit is `1_048_576` bytes and `1_000` non-empty data rows; exceeding either raises
  `RosterImportTooLarge`.
- `csv.reader(..., strict=True)`; a column-count mismatch raises `RosterImportMalformed`.
- Fully blank lines are skipped. `row_number` is the physical line number starting at 2 for the
  first data row; `total_rows` counts non-empty data rows.
- Values are trimmed. `institutional_id` is normalized with
  `User.objects.normalize_institutional_id`; Campus/College codes with `normalize_code`.
- Blank or invalid identity/codes produce `INVALID` rows. A duplicate normalized
  `institutional_id` marks the later row `INVALID` with
  `duplicate institutional_id in CSV; first occurrence is row N`; the first row remains in the
  report. Committing any duplicate issue raises `RosterImportDuplicateIdentity` (422); any other
  issue raises `RosterImportInvalidRows` (422).

## 4. Classification

Resolution is read-only and uses normalized codes: Users by institutional ID, active Campuses by
code, active Colleges by code under the resolved Campus, and profiles for resolved Students.
Classification order:

| Condition | Action | Message |
|---|---|---|
| Row unparsable / blank required value / duplicate ID | `INVALID` | Specific parse message |
| Institutional ID does not resolve | `CONFLICT` | `institutional_id does not resolve to an existing account` |
| Account is not `STUDENT` | `CONFLICT` | `the account does not have the STUDENT role` |
| Student is inactive | `CONFLICT` | `the Student account is inactive` |
| Campus is unknown or inactive | `CONFLICT` | `campus_code does not resolve to an active Campus` |
| College is unknown, inactive, or under another Campus | `CONFLICT` | `college_code does not resolve to an active College beneath that Campus` |
| Profile has `current_program` or `placement_effective_at` | `CONFLICT` | `the current placement contains facts this import cannot safely replace` |
| Verified placement with a different target College | `CONFLICT` | `the current placement is verified and cannot be overwritten by roster import` |
| Verified placement with the same target College | `NOOP` | `the placement already matches; verified placement unchanged` |
| Unverified placement with the same target College | `NOOP` | `the placement already matches` |
| No placement or a different target College | `SET` | `the placement will be assigned` / `the placement will be updated` |

`student_lifecycle_status` is not used as an import gate. Report `valid` is true only when
`conflict_count == 0 and invalid_count == 0`; rows are sorted by `row_number`.

## 5. Dry-run and commit

Dry-run (`dry_run=true`):

1. Parse the CSV and collect parse issues.
2. Resolve without row locks.
3. Classify and return the report with `committed=false`.
4. No profile/account write, verification change or audit event.

Commit (`dry_run=false`):

1. Parse; raise duplicate-identity (422) or invalid-rows (422) before writing.
2. Enter `catalog_dependent_write` (shared advisory catalog gate) and `transaction.atomic()`.
3. Re-resolve under deterministic locks: Students (`select_for_update(of=("self",))`, ordered by
   `pk`), Campuses and Colleges (ordered by `pk`, College locked with its Campus), and profiles
   (ordered by `student_id`).
4. Reclassify. Any `CONFLICT` raises `RosterImportConflict`; nothing is written.
5. Apply only `SET` rows, sorted by Student `pk`, by calling the existing
   `set_current_placement(student_id=..., college_id=..., expected_campus_id=..., context=...)`.
   `NOOP` rows never call the writer.
6. If `set_count > 0`, record one `student_academics.roster.imported` event with
   `{total_rows, set_count, noop_count}` and no target or row content.
7. `IntegrityError` rolls back and raises a synthetic row-0 conflict:
   `student academic state changed while the roster import was committing`.
8. Return the locked/reclassified report with `committed=true`.

Each applied row keeps the normal `student_academics.placement.set` event with previous/new
College IDs. An all-`NOOP` commit returns `committed=true` with no placement or summary event. A
rolled-back commit produces no events.

## 6. API

| Item | Value |
|---|---|
| Method and path | `POST /api/v1/student-academics/imports/csv` |
| Operation ID | `studentAcademicsImportRosterCsv` |
| Summary | `Validate or commit an approved Student academic roster CSV` |
| Auth | `session_auth`; `_require(request, "student_academics.import", recent_mfa=True)` for both modes |
| Request | multipart `file`; optional `dry_run` (default `true`) |
| Response | `RosterImportResponse` |
| Errors | 401, 403, 409, 422 |

Error mapping, in order: `RosterImportTooLarge` → 422 `csv_import_too_large`;
`RosterImportUnsupportedHeaders` → 422 `csv_import_unsupported_headers` (checked before
malformed); `RosterImportMalformed` → 422 `csv_import_malformed`;
`RosterImportDuplicateIdentity` → 422 `csv_import_duplicate_identity` with details;
`RosterImportInvalidRows` → 422 `csv_import_invalid_rows` with details; `RosterImportConflict`
→ 409 `csv_import_conflict` with details. Details are
`{row_number, institutional_id, message}` only — no email or student names.

## 7. Frontend

- **Access and gate.** `canImportStudentAcademics(user)` checks `.import`;
  `StudentAcademicRosterImportGate` shows “Academic roster import unavailable” otherwise. The
  route uses `pageSheetWidth`, a `PageHeader` titled “Import academic roster” and a back link to
  Student Academic Records.
- **Copy.** The page states that the CSV reconciles current College placement only, does not
  create/update accounts, identity, roles, status, Program, enrollment, periods or graduation;
  missing Students keep their placement; verified placements are protected; imports are
  unverified and do not confirm enrollment; headers are
  `institutional_id,campus_code,college_code`; `program_code` and `email` are unsupported; the
  limit is about 1 MiB and 1,000 non-empty rows.
- **Template and references.** A data-URI download named
  `compass-academic-roster-import.csv` contains exactly
  `institutional_id,campus_code,college_code\n`. The active Campus/College table uses the
  generated organization client and loads only when its disclosure is opened.
- **Validation.** File input label is exactly `CSV file` (`accept=".csv,text/csv"`). “Validate
  CSV” posts `dry_run=true`. The report shows Total/Set/No change/Conflict/Invalid and rows with
  Row, Institutional ID, Student, Current College, Target Campus/College, Action and Message;
  action labels are Set/No change/Conflict/Invalid.
- **Commit readiness.** The commit action requires the same `File` object that was validated, a
  valid uncommitted report, no prior commit conflict, and `set_count > 0`. An all-`NOOP` valid
  report shows “No placement changes are needed.” without a commit action. A report with a
  conflict never renders the commit action.
- **Commit review.** `ConsequentialActionDialog` is titled `Import N placement(s)?`, shows the
  real counts, states that imported placements are unverified, do not confirm enrollment and
  remain subject to server checks; confirm is “Import placements”, pending is “Importing
  placements…”. Confirmation posts `dry_run=false`.
- **Success and failure.** Success keeps the committed report visible, shows “Academic roster
  import completed. Review the committed result below.”, and invalidates the placement-list query
  and each `SET` student's record query. A 409 sets a conflict state that requires revalidation
  before another commit; 422 details render as row issues; structural errors render a page alert.
- **Step-up.** `useStepUpContinuation` + `StepUpDialog` preserve the selected file and reviewed
  report across recent-MFA/setup prompts; a commit is never silently replayed.
- **Entry points.** The staff page shows a secondary `Import` link with accessible name
  “Import academic roster” only with `.import`; the command palette adds the deep destination
  `Organization › Import academic roster` with CSV/roster search aliases.

## 9. Implementation notes

- `import_student_academic_roster` is decorated with `catalog_dependent_write`, so both dry-run
  and commit take the shared advisory catalog gate; only the commit path takes row locks. This
  keeps the academic writer coherent with catalog mutations and does not change dry-run data.
- The module deliberately does not import `compass.account_management.*`; the small CSV helpers
  are local to avoid an import cycle.
