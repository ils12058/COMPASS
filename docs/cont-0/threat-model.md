# Threat model and risk disposition

Trust boundaries: browser → session/API → capability+source service → PostgreSQL ciphertext/key-bearing application → notification/worker/external channels. UUIDs, links, submitted scope lists, frontend capabilities and realtime hints are untrusted inputs. The application host can decrypt; at-rest encryption does not protect against a compromised key-bearing host. Current absence of grants is not an existing grant bypass: “missing” below usually means a **required future control**.

Risk ranks are design priorities, not asserted exploitability scores. B = backend/domain owner; F = frontend owner; O = deployment/data operator; G = GCO/privacy policy owner; S = security reviewer. Roles name responsibilities; no institutionally assigned individual owner is invented. All future controls require regression evidence before activation.

## Current findings requiring separate attention

CONT-F01 is a confirmed present audience mismatch under the new specification. CONT-F03's full Inventory Context projection is an existing tested relationship-based path, not by itself a demonstrated authorization vulnerability; copying it wholesale into grants would create a new over-disclosure risk. CONT-F08 is a malformed persisted-link defense gap: normal write services validate relations, but overview should not trust a mismatched link. No exploit path for arbitrary link injection was demonstrated.

Inspected Counseling/Context endpoints lack explicit route-level no-store headers; actual browser/proxy persistence was not measured. Scope header hardening and invalid-link projection checks as independent focused security work if approved; do not bury them in CONT-1B terminology edits. The new continuity paths require both controls before activation regardless of the existing path's final disposition.

## Release evidence required

For T01–T24, CONT-4 must attach synthetic test outcomes, current actor/resource matrix and browser scenarios, with exact candidate SHA, tested database lineage and policy sign-off. Concurrency claims require real PostgreSQL transactions, not mocks alone. Encryption/graph checks in CONT-0 provide current codec/source confidence, not proof future grants/reset workflows are secure. Security reviewer and GCO/privacy owner must explicitly accept residual information persistence and approval/delegation scope; unresolved high risks block new professional sharing.
