# Encryption, migration and clean cutover

This is a future execution specification. CONT-0 did not read live secrets, connect to a database, execute migrations, provision keys, inspect records or change deployment configuration.

## Current cryptographic contract

Evidence: [summary adapter](../../be/compass/counseling/shared_summary_content.py), [shared primitive](../../be/compass/confidential_data/crypto.py), [safe failures](../../be/compass/confidential_data/errors.py), [rotation command](../../be/compass/counseling/management/commands/rotate_counseling_shared_summary_encryption.py), [settings](../../be/config/settings.py), [runtime inventory](../../be/deploy/runtime-secrets/runtime_secrets.py), [staging manifest](../../be/compose.staging.yaml), [frozen test oracle](../../be/tests/encryption_oracles/shared_summary_content_v1.py).

| Property | Verified behavior / consequence |
| --- | --- |
| Keyring | Required `COUNSELING_SHARED_SUMMARY_ENCRYPTION_KEYS`, optional standard `_FILE` input. Ordered canonical Fernet keys; first encrypts, all can decrypt. Empty/malformed/duplicate keys fail startup safely. |
| Separation | Settings reject reuse with Django/TOTP/Push/Routine keys; later keyring declarations compare against Summary and earlier purpose rings, covering Referral, Exit, Inventory, Graduate Tracer, account profile, feedback, messages, assessments and Follow-Ups. Every relevant pairwise reference must use the renamed setting. Parsing alone does not prove separation. |
| Envelope | Version 1, exact authenticated JSON keys: `schema_version`, `counseling_shared_summary_id`, `encounter_id`, `payload`; payload exactly `{content: string}`. Whitespace/Unicode preserved; NUL/unrepresentable input rejected. Binding lives **inside authenticated plaintext**, not external AEAD additional data. |
| Authorization | Callers must select authorized rows before `read_shared_summary_content`. ORM access does not decrypt automatically. Encryption is application-at-rest protection, not end-to-end encryption or authorization. |
| Failure | Missing, undecryptable, malformed, unsupported schema, binding mismatch; safe domain exception. Authorized corruption yields generic `counseling_shared_summary_content_unavailable`; no fallback blank body. Missing configuration raises a safe configuration failure. |
| Rotation | Command verifies exact existing envelope, locks real-update rows, paginates by UUID in batches, commits/resumes, and rewraps via MultiFernet.rotate. `--dry-run` verifies/counts. Publication/timestamps/Audit/Notifications are not rewritten. Bounded identifiers/reasons only; corruption causes non-success and remains unchanged. |
| Binding rename | `rotate` preserves the original plaintext binding and token timestamp. Even using the identical key under a new setting cannot make the old envelope match `student_session_summary_id`. Key rotation and envelope conversion are different operations. |
| Provisioning | Source secret `counseling_shared_summary_encryption_keys`, required runtime `_FILE` variable, web/worker/Beat mounts, inventory validator and examples. No live value was read. |

The new contract should be `STUDENT_SESSION_SUMMARY_ENCRYPTION_KEYS`, bound to `student_session_summary_id` and `encounter_id`, with an exact versioned payload. Keep schema version 1 if defining a newly named resource format; never claim old/new formats are interchangeable. A retained-data converter explicitly recognizes old v1 and writes/verifies new v1. Do not add dual-binding decryption to the active adapter.

The optional Handoff requires a new independent `COUNSELOR_HANDOFF_SUMMARY_ENCRYPTION_KEYS` and adapter using the same primitive, with binding at least Handoff UUID + grant UUID + Student UUID + author + recipient. Startup separation must cover every existing purpose/security ring. Keys are generated/provisioned only in separately authorized environment work; this audit proposes names and dependencies, not key material.

## Compare the three routes

| Route | Suitable when | Required work / tradeoff |
| --- | --- | --- |
| A — retain data | Any affected communication/history has retention value, or disposable status is unknown | Offline exact old-envelope decrypt, validate, rebind and encrypt to new format; preserve UUID/Encounter/text/publication/timestamps; transform Notification/capability contracts; compare structural counts and encrypted verification without printing bodies. More tooling and rollback effort. |
| B — scoped destructive cutover | Authorized owner confirms **all affected Summary data and related synthetic notification/delivery rows** disposable | Stop consumers; inventory only approved scope; remove affected synthetic Summary rows and associated synthetic Notifications/EmailDelivery/Push-delivery references according to verified relations, retain unrelated data and immutable Audit; apply additive schema/contract changes. Cannot undo deleted data by rolling code back. |
| C — regenerate synthetic fixtures | B is approved, or a fresh installation/demo database is created | Update deterministic IDs/manifests/counters/workflow helpers, encrypt seed bodies with new adapter, run seed/verify under explicitly authorized non-delivery conditions. Complements B; does not authorize a full environment reset. |

**Primary recommendation: B + C, scoped to this resource**, because the request permits disposable non-production data and the repository has an explicit synthetic Dataset v1. This is conditional: no live verification of disposability or pending delivery population occurred. If any record must be retained, use A. Do not reset the whole database, authentication, object storage, unrelated professional records or Audit merely to avoid an additive rename. Full-database recreation requires a separately enumerated scope/approval and operational runbook.

## Canonical migration lineage

Current Counseling has only [`0001_canonical_baseline`](../../be/compass/counseling/migrations/0001_canonical_baseline.py), already ciphertext-only. [ADR-116](../../be/docs/decisions/ADR-116-canonical-baseline-and-staging-dataset-v1.md), [manifest](../../be/compass/common/canonical_migrations.json) and [history guard](../../be/compass/common/canonical_baseline.py) preserve baseline hashes, register additive files and refuse pre-canonical databases. ADR-080's old plaintext backfill migrations no longer exist in this lineage. Do not resurrect, edit, fake or squash the baseline.

Likely CONT-1B migration set: additive Counseling `0002_student_session_summary_contract` for model/table/reverse relation/constraint state, and an Accounts additive migration or explicit controlled transform for persisted capability codes. Final names/dependencies are generated and reviewed in that implementation. Register additive migrations without changing immutable baseline hashes. Baseline historical class names are permitted history, not dual runtime models.

No other baseline model has a foreign key to Shared Summary; its current one-to-one points **to** Encounter, and Notifications/Audit use generic type/UUID identifiers. Verify this again before migration generation. A table rename does not fix generic strings. Evaluate installed Django content types, if any, and database-specific named constraints/indexes; do not invent permissions or manually rewrite unrelated metadata.

For B, purge authorized rows using old schema before rename. New schema migration should refuse unexpected retained old-format rows, rather than silently strand them. For A, a temporary offline converter must support historical table/model selection, two explicitly supplied protected keyring file inputs and exact old/new codecs; do not load a permanent old configuration alias in current settings. Convert only under maintenance, with checkpointed all-row verification and an atomic/controlled failure strategy. New schema migration must verify expected state before enabling new code. Fresh empty installs need **only new runtime keyring names**, no old secret. Old code cannot run after bodies are rebound or the table renamed.

## Rollback and reset

Before any data/schema mutation, abort and retain the old consistent runtime. After conversion/rename, **code-only rollback is unsafe**. Stop consumers and restore the tested compatible image+frontend+schema+data+manifest+keyring unit, or run a verified inverse converter/schema route for retained A. Never bring old code up against new binding/table names. A forward rollback must preserve publication and notification idempotency.

B's deleted content is recovered only from an authorized protected recovery unit, or replaced with explicitly synthetic regeneration accepted as loss. Old Audit rows remain evidence, even where source rows no longer exist. Never invent “restored” professional history. A fresh-install rebuild is not proof an existing retained upgrade works, and disk-only graph agreement is not proof PostgreSQL migrations execute. These remain future cutover blockers.
